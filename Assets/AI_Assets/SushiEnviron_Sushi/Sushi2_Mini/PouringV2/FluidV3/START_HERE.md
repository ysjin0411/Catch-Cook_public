# FluidV3 — 병으로 따르는 입자 유체 미니게임

이번 버전이 최신 구현 예제입니다. 같은 이름의 이전 CodeSamples를 함께 연결하지 마세요.
기존 씬·게임 스크립트·ProjectSettings는 변경하지 않았습니다.
현재 파일은 직접 적용하기 전까지 컴파일되지 않도록 .cs.txt / .shader.txt로 제공됩니다.

## 먼저 볼 것

- Preview/Replay.html: 이 파일을 브라우저에서 열면 실제 C# 솔버가 계산한 15초를 재생/정지/탐색할 수 있습니다.
- Preview/Comparison.png: 주입 중과 안정 후 비교.
- Preview/Validation.txt: 검사 결과.
- Preview는 Unity 화면 캡처가 아닙니다. 실제 좌표를 같은 밀도 공식으로 재생한 별도 검증 자료입니다.
- 플레이 모드의 실제 코드는 녹화 재생이 아니라 매 순간 새로 계산합니다.
- 프리팹은 아직 생성하지 않았습니다. 아래 편집기 메뉴를 사용자가 실행하면 만들어집니다.

## 무엇이 추가됐는가

1. 입자 사이의 속도 교환(점성).
2. 이웃 밀도와 근거리 밀도 계산.
3. 밀도 압력으로 입자를 밀어내는 위치 보정.
4. 아래가 좁고 위가 넓으며 윗면이 열린 컵 경계.
5. 컵에 들어온 입자를 유지하여 물이 옆으로 퍼지고 출렁이는 계산.
6. 입자 밀도 텍스처와 경계 합성 셰이더.
7. 병의 기울기 및 실제 Mouth RectTransform에서의 발사.
8. 담긴 양, 공중의 양, 유실량과 발사 대기량의 분리.
9. 연타 게이지, 수위 목표, 안정 후 성공 또는 즉시 성공.
10. 별도 테스트 프리팹 생성 도구.

이 버전은 정면 화면용 **사용자 정의 2D 입자 유체 계산**입니다.
Rigidbody, Rigidbody2D, Unity Physics Core를 사용하지 않습니다.
입자마다 GameObject를 만드는 이전 예제도 사용하지 않습니다.
앞서 요청한 '방울 오브젝트'의 역할을 이번에는 위치·속도·양을 가진 입자 데이터로 처리합니다.
월드 카메라를 회전해서 보는 진짜 3D 유체나 3D 메시 용접 구현은 아닙니다.
참고하신 2D 입자+메타볼 방식에 맞춘 선택입니다.

고정된 사다리꼴 컵과 수백 개 이하 입자를 위한 소규모 CPU 예제입니다.
범용 SPH 라이브러리나 원작의 내부 코드를 복제한 것은 아닙니다.
다른 모양의 컵, 이동하는 컵, 임의의 Collider는 자동 인식하지 않습니다.

## 1. 가져오기

1. Code 폴더의 C# 네 파일에서 마지막 .txt만 제거합니다.
   예: FluidSimulation.cs.txt → FluidSimulation.cs.
2. 셰이더도 UI_FluidDensity.shader.txt → UI_FluidDensity.shader로 바꿉니다.
3. Editor/FluidDemoBuilder.cs.txt → Editor/FluidDemoBuilder.cs로 바꿉니다.
4. Editor 폴더 위치를 유지합니다. 편집기 코드를 런타임 폴더로 옮기지 않습니다.
5. Tests/ValidationRunner.cs.txt는 이름을 바꾸지 않습니다. Unity용 컴포넌트가 아닙니다.
6. Unity 컴파일이 끝나는지 확인합니다.
7. asmdef를 사용한다면 런타임에 Unity.InputSystem과 UnityEngine.UI를 참조하고,
   편집기 어셈블리는 Editor 플랫폼 전용으로 구성합니다.

기존 PouringV2/CodeSamples의 PouringController/PouringView/MetaballFluidRig는 이번 데모에 붙이지 않습니다.
이전 OBJ 컵 물리 메시도 이번 솔버에는 필요하지 않습니다.

## 4. 물리 계산의 순서

고정 시간 간격은 1/120초입니다.

1. 이웃 입자의 속도를 조금씩 나눠 점성을 표현.
2. 중력을 적용하고 다음 위치를 예측.
3. 반경 H=0.28 안의 입자들을 찾아 밀도·근거리 밀도를 계산.
4. 밀도 압력과 근거리 압력으로 위치를 양쪽으로 보정.
5. 과한 겹침을 최소 거리 제약으로 해소.
6. 컵 바닥과 기울어진 벽 바깥으로 나가지 않도록 보정.
7. 보정된 위치 차이에서 다음 속도를 복구.
8. 화면 밖 또는 컵 밖으로 넘어간 입자를 유실량으로 기록.

이웃은 모든 쌍을 검사하는 O(N²) 방식입니다.
최대 384개로 제한하고, 밀도 보정은 스텝당 2회입니다.
작은 컵 미니게임용이며 수천 개로 늘릴 때는 공간 해시 등 이웃 검색을 먼저 바꿔야 합니다.

컵은 수학적 경계입니다:
- 바닥 y=-2.4, 입구 y=0.4.
- 아래 반너비 0.72, 위 반너비 0.84.
- 입자 충돌 반지름 0.055.
- 윗면은 열려 있으므로 충격이 크면 액체가 밖으로 나올 수 있음.
- 입자가 입구를 지나 들어왔는지 추적하여 컵 옆에서 들어온 물이 벽 안으로 순간이동하지 않게 함.

이전 버전처럼 바닥보다 낮은 위치에 도착해야 수위가 오르는 판정을 사용하지 않습니다.
입구를 통과한 입자를 컵 내부 양으로 기록하고, 입자 자체는 계속 시뮬레이션합니다.
밖으로 빠져나가면 해당 양은 담긴 양에서 빠지고 유실량으로 이동합니다.

## 5. 밀도와 셰이더

각 입자 주변에 다음 필드를 더합니다:

q = Max(0, 1 - distanceSquared / radiusSquared)
density += q × q

실제 렌더 영향 반경은 0.21입니다.
가까운 입자 사이에서는 두 필드가 더해져 임계값 0.5를 넘기므로 경계가 연결됩니다.
컵 안의 수면도 실제 입자에서 나오며, 높이 기반 사각형이나 별도의 사인파 수면은 사용하지 않습니다.

DensityView는 300×360 RFloat 텍스처에 입자 주변 픽셀만 누적합니다.
셰이더는 그 텍스처를 읽고 경계를 추출하며 얕은 명암을 얹습니다.
입자 수가 늘 때 GPU 픽셀마다 모든 입자를 다시 검사하는 이전 48개 배열 셰이더보다
픽셀 셰이더 비용을 예측하기 쉽습니다. 대신 CPU 누적과 텍스처 업로드 비용이 있습니다.

RFloat 지원 여부를 검사합니다. 미지원 기기용 대체 구현은 포함하지 않았습니다.
별도 카메라·RenderTexture·URP RendererFeature·외부 패키지는 필요하지 않습니다.
외부 UI stencil Mask 지원은 포함하지 않았습니다. FluidOutput을 Mask 아래에 넣지 마세요.

## 6. 조작과 양 계산

연타 입력:
- 자동 왼쪽 이동: 초당 0.45.
- 한 번 누르면 오른쪽으로 0.12.
- 0~1 범위 제한.
- 0.4~0.6이 입력 게이지의 노란 영역.

유량:
- 왼쪽에서는 0~0.12.
- 노란 영역에서는 0.12.
- 오른쪽에서는 최대 0.34.
- 단위는 컵 전체 단면적에 대한 초당 정규화 양.

주입량은 Pending에 누적됩니다.
입자 하나의 양은 ParticleArea / CupArea입니다.
기본 ParticleArea는 0.021, CupArea는 4.368입니다.
이 값은 3D 리터 단위가 아니라 현재 2D 솔버의 입자 간격에 맞춘 게임용 양 보정값입니다.
한 방울보다 작은 마지막 양도 버리지 않고 마지막 입자에 할당합니다.
풀에 빈 슬롯이 없으면 예산을 보존합니다.

물결 최고점 대신 보존된 입자 양을 더하여 기준 수위를 계산합니다.
테이퍼 컵의 단면적을 고려하므로 단순히 양=높이로 놓지 않습니다.
솔버는 완전 비압축성 유체가 아니므로 기준 수위와 순간적인 실제 수면은 다를 수 있습니다.
기준 양을 표시하는 숫자와 노란 범위를 함께 보여주며, 외형 튜닝 시 ParticleArea도 다시 보정해야 합니다.

판정:
- 기본: 압력 0, 발사 대기와 공중 입자 없음, 평균 입자 속도 0.25 미만인 상태가 0.5초 지속,
  기준 수위 68~78%면 성공.
- 78% 초과는 실패.
- 제한 시간 12초.
- Immediate Success를 켜면 68% 도달 즉시 성공하는 사용자 원안을 사용.
- 종료 뒤에도 이미 담긴 입자를 계속 계산하므로 출렁임이 가라앉는 모습을 볼 수 있음.
- 결과가 확정된 후의 외형 변화는 이미 확정한 결과를 바꾸지 않음.

제한 시간이나 목표 범위를 바꾸려면 Session의 수치와 프리팹 목표 표시 좌표를 함께 수정하세요.
현재 예제는 고정 설정으로 간결하게 구성했습니다. 메뉴별 설정을 늘릴 때는 설정 객체로 분리하면 됩니다.

## 8. 팀 프로젝트에 연결

독립 테스트가 끝난 뒤 다음 순서로 연결합니다.

1. Demo On Enable을 끕니다.
2. 실제 상호작용 InputActionReference를 Tap Reference에 지정합니다.
3. 음료 대기 손님과 주문을 저장하고 제공권을 확보합니다.
4. 플레이어의 이동과 기존 음료 Hold 누적 처리를 중지합니다.
5. Completed 이벤트를 구독합니다.
6. 패널을 활성화하고 Begin(주문 색)을 호출합니다.
7. Success에서만 같은 손님·주문·제공권이 유효한지 다시 검사하고 제공을 완료합니다.
8. 성공·실패·취소 모든 경로에서 제공권 반환, 이동 복구, 이벤트 구독 해제를 처리합니다.
9. 손님 이탈, 주문 변경, 플레이어 거리 이탈은 Cancel()로 전달합니다.

읽어본 기존 파일 기준:
- SushiInteractor의 플레이어 음료 분기에 미니게임 시작을 연결.
- 미니게임 중 GuestNPC.TickHoldInteract를 계속 호출하지 않음.
- ServingNPC의 자동 제공과 청소의 Hold 처리까지 바꾸지 않음.
- 성공 시 임의로 큰 deltaTime을 넣어 완료시키지 말고,
  주문·소유권을 검증하는 완료 진입점을 별도로 마련.

실제 손님에게 보상을 지급하거나 주문 상태를 바꾸는 코드는 이 독립 예제에 포함하지 않았습니다.
기존 게임의 상태·소유권 규칙에 맞춘 연동 지점으로 안내합니다.
이미 프로젝트를 수정하지 말라는 요청에 따라 해당 게임 파일을 바꾸지 않았습니다.

## 9. 검사 결과와 실제 Unity 확인 항목

완료한 검사:
- 런타임 C# 4개와 편집기 코드가 Unity 6000.0.68f1 라이브러리를 참조하여 컴파일됨.
- 정상 연타 입력 → Success, 기준 수위 약 75.9%.
- 컵 내부 입자 155개 유지.
- 주입 중 평균 속도 약 1.039 → 안정 후 약 0.021.
- 1800스텝 전체에서 유한한 좌표, 바닥 경계, 물량 보존 확인.
- 미입력 시간 초과, 과다 입력 실패, 취소, 풀 한도 확인.
- 실제 입자 좌표 기반 재생 자료와 비교 이미지 확인.

아직 실행하지 않은 검사:
- Unity에서의 Shader 컴파일과 실제 RawImage 출력.
- 메뉴를 통한 프리팹 생성 및 Play 모드 입력.
- 목표 기기 성능.
- Sushi2의 손님·보상·플레이어 상태 연동.

적용 후 체크 순서:
1. Console의 C# 및 Shader 오류가 없는지 확인.
2. 테스트 프리팹에서 물이 병 입구에서 나오는지 확인.
3. 컵 벽과 바닥을 지나가지 않는지 확인.
4. 입력 중지 뒤에도 입자가 남고 안정되는지 확인.
5. 기준 수위 숫자와 안정된 수면이 목표 영역에서 과하게 어긋나지 않는지 확인.
6. SPACE를 길게만 눌렀을 때 연타로 계산되지 않는지 확인.
7. 일시정지, ESC, 패널 비활성화 시 결과가 한 번만 전달되는지 확인.
8. 마지막으로 실제 손님 주문과 연결.

컵을 다른 모양으로 교체하거나 입자 간격·압력을 크게 변경하면 수위 보정값도 다시 맞춰야 합니다.
Profiler에서 CPU 솔버와 텍스처 업로드 시간을 확인하고, 필요하면 최대 입자 수와 해상도를 줄이세요.
